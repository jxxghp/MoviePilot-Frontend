# 原生操作菜单契约

此契约用于 App 接管既有操作菜单。内置卡片通过可选 `card-menus.v1` 能力使用 UIKit 上下文菜单；普通网页、PWA、旧 App 和未完成能力协商的文档保留原菜单交互。业务回调仍由现有 Vue 组件执行。

网页内部的独立按钮通过 `standalone-menus.v1` 使用按内容量测、最高三分之二屏的原生列表，包括文件地址栏、资源排序、设置中的添加菜单，以及个人信息的账号安全菜单。已由 App 接管的顶栏、底栏和用户二级菜单继续使用现有系统原生菜单。

`src/native/menu.ts` 的 `NativeMenuSource` 提供原页面实时菜单及回调。`NativeOperationMenu` 只传展示数据，不包含函数、业务 API 或可执行脚本。卡片来源使用 `card`，独立按钮使用 `standalone`。

菜单项目按原顺序声明，可包含动作、子菜单、带标题分组和分隔条，并保留图标标识、副标题、语义颜色、禁用、加载、选中、危险操作及选择后保留菜单的语义。项目 ID 必须代表具体业务动作，不使用数组位置。输入表单、路径树、日期或 Cron 编辑器不属于操作菜单。

适配层只有在宿主能力协商完成、原生布局接管且文档处于前台后才能提供 `NativeMenuContext`。上下文变化会撤销全部来源和展示，当前组件必须重新登记；卸载需调用登记返回的注销函数。相同 owner/menu 的新注册会替换旧代次，旧组件不能注销新来源。

`canPresent` 供适配层预检是否可隐藏原入口，不打断已展示菜单。`open` 读取当前状态并返回单次 `presentationId`。`select` 核对该标识及当前完整声明，等待调用方提供的菜单关闭/绘制交接，再重新校验并调用最新业务闭包；同一展示只能选择一次。关闭、注销、替换、进入后台、切页或换文档均可撤销等待中的选择。保留菜单的动作执行后也需要重新读取并获得新标识，不能复用旧票据。

最多允许三层、96 项和 24 KB 展示 JSON；文字按 UTF-8 限额校验。过大、重复 ID、缺少回调或无法完整投影时整份声明拒绝，适配层不能隐藏原入口或只展示截断后的部分菜单。原回调的异常继续交给原调用路径处理。

`AppMenu` 的 `native-menu` 声明绑定真实 VMenu 激活器。资源单项筛选和综合筛选属于复杂表单，继续由原生弹窗承载原 HTML 界面，保留多选、全选、清空、分类布局与原业务回调，不投影成独立原生操作列表。

卡片使用 `src/native/card.ts` 的局部 `vNativeCardMenu` 指令绑定明确的根元素。`NativeCardMenuBinding` 读取原菜单及原业务回调，以稳定实体 key 区分虚拟列表复用；实体变化或卸载立即撤销旧代次。同一实体刷新只更新 getter，选择前仍核对最新完整声明。业务 key 留在页面内，跨桥只使用短 owner 标识。

`NativeCardMenuRegistry` 默认不读取菜单、测量位置、添加监听器或修改样式。适配层提供有效上下文并在新页面 DOM 提交后调用 `synchronize`，才能读取当前可见来源的 `targets`。上下文变化清空原注册，不能自动把旧页面带入新路由。隐藏、脱离文档、无效位置、不可用模式或不完整声明均不能成为目标。

内置声明覆盖媒体海报、订阅、下载、站点、插件及文件夹、工作流、文件、资源及历史记录、分类规则、缓存和数据库备份。MediaCard 长按提供原搜索、订阅按钮的动作，保留这两个按钮及原权限、当前订阅状态和季选择；合集不新增动作。只有原菜单触发器标记 `data-native-card-menu-trigger`；移动文件详情入口和独立内联功能按钮保留。标记本身不隐藏按钮，也不禁用选字。远程插件可以用同一显式契约登记，但直接导入 Vuetify 的第三方菜单不会自动获得适配。

## 卡片接管与兼容

宿主在 `MoviePilotNative` 中提供 `cardMenusVersion: 1`，双方在 `web.ready` / `host.configure` 中确认 `card-menus.v1`，且原生布局接管完成后，`NativeCardMenuAdapter` 才开始工作。仅当前完整、可见的来源添加 `data-native-card-menu-ready`，隐藏被标记的真实菜单触发器。原生布局接管后，所有卡片正文均禁用文字选择及 WebKit 图片预览，包括没有操作菜单的卡片；输入框、文本域和可编辑内容保留文本选择，原按钮仍可点击。普通 Web/PWA 不应用这项规则。

触摸开始时关闭 HTML 菜单，等待 Vue 更新及绘制，再发送 `cardMenu.prepare`，携带完整菜单、当前卡片矩形、触点与 viewport。原生使用 `UIContextMenuInteraction` 和该卡片的真实预览；滚动、短按、位置变化或两秒内未展示均撤销准备票据。`cardMenu.opened` 确认系统已经展示，`cardMenu.dismissed` 仅取消，`cardMenu.select` 只带展示与项目标识，等系统收起后由网页重新校验并执行一次原回调。`keepOpen` 动作成功后通过 `cardMenu.refresh` 更换单次票据。

系统展示期间忽略 WebKit 重发或透传到卡片的按下事件，不用新准备票据提前取消当前菜单；系统关闭后才接受下一次卡片触摸。

每张卡片保留以原名称标注的辅助操作按钮，VoiceOver 和键盘可打开相同项目的原生操作列表；列表按内容量测，最高为可用屏幕的 2/3，长菜单内部滚动。辅助入口不显示旧三点按钮。该列表不代表所有独立工具栏菜单已经接管，非卡片菜单仍需各自显式登记。

后台、身份变化、路由切换、来源卸载及桥接释放均撤销当前菜单，并恢复原菜单入口；恢复前台后重新登记当前 DOM。卡片禁选跟随原生布局的接管状态。消息必须匹配当前文档会话及路由，旧菜单或重复选择不能跨上下文执行。
