# 原生操作菜单契约

此契约用于 App 接管既有操作菜单，目前只提供声明与本地注册表，默认关闭，尚未连接宿主能力、DOM 或手势。普通网页、PWA、旧 App 和现有菜单均保持当前交互。

`src/native/menu.ts` 的 `NativeMenuSource` 提供原页面实时菜单及回调。`NativeOperationMenu` 只传展示数据，不包含函数、业务 API 或可执行脚本。卡片来源使用 `card`，独立按钮使用 `standalone`。

菜单项目按原顺序声明，可包含动作、子菜单、带标题分组和分隔条，并保留图标标识、副标题、语义颜色、禁用、加载、选中、危险操作及选择后保留菜单的语义。项目 ID 必须代表具体业务动作，不使用数组位置。输入表单、路径树、日期或 Cron 编辑器不属于操作菜单。

适配层只有在宿主能力协商完成、原生布局接管且文档处于前台后才能提供 `NativeMenuContext`。上下文变化会撤销全部来源和展示，当前组件必须重新登记；卸载需调用登记返回的注销函数。相同 owner/menu 的新注册会替换旧代次，旧组件不能注销新来源。

`open` 读取当前状态并返回单次 `presentationId`。`select` 核对该标识及当前完整声明，等待调用方提供的菜单关闭/绘制交接，再重新校验并调用最新业务闭包；同一展示只能选择一次。关闭、注销、替换、进入后台、切页或换文档均可撤销等待中的选择。保留菜单的动作执行后也需要重新读取并获得新标识，不能复用旧票据。

最多允许三层、96 项和 24 KB 展示 JSON；文字按 UTF-8 限额校验。过大、重复 ID、缺少回调或无法完整投影时整份声明拒绝，适配层不能隐藏原入口或只展示截断后的部分菜单。原回调的异常继续交给原调用路径处理。

后续 UIKit 展示、卡片位置和预览、辅助操作、能力协商及最高 2/3 屏独立菜单弹窗需要另行接入和验收，当前基础契约不代表已完成这些交互。
