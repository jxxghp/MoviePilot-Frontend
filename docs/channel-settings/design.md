# 消息渠道设置设计

导航：[实施计划](plan.md) · [任务清单](tasks.md) · [验证](validation.md) · [使用说明](../channel-authorization.md)

## 设置入口与布局

「配置 → 消息 & 交互」只展示一组「消息渠道」卡片。每个共享连接显示一次，卡片按钮遵循下载器配置页，额外提供更多菜单。菜单提供连接配置、通知管理及能力允许的交互管理。点击卡片默认打开连接配置，通过弹窗切换图标切换页面，不嵌套标签页。

渠道授权及全局通知设置位于卡片组右侧。新建图标、文字保存、拖拽排序、删除确认和状态提示复用主程序配置页风格。删除、切换、关闭按顺序放在弹窗右上角。表单间距、行高、底色和圆角沿用既有组件，条件内容不撑高相邻选择框。

## 草稿与保存

连接、通知、交互各有草稿、revision 和显式保存入口；切换页面保留各自草稿，不自动保存。后端冲突提示用户重新加载，不能用另一资源的旧版本覆盖当前配置。连接凭据可再次编辑，空白保留已有受保护值，公开身份字段遵循后端合同。

连接删除显示影响并提交三个资源版本，成功后移除卡片与排序引用。名称可重用，但新连接必须采用新的稳定 ID；不能复用被删除连接的授权及业务身份。

## 规则交互

首次使用策略为人工审批、人工审批 + 规则审批、规则审批、无需审批。无需审批显示安全提示。首次使用规则可指定允许搜索、订阅、下载及定时任务。自动下载为关闭、规则、全部，按渠道单独保存。实际执行始终由后端复核权限。

规则组包含导入、清空、分享；每条规则为一张卡片，提供名字、开关、删除、编辑及条件摘要。单条规则在独立弹窗编辑，取消保持原值。规则计数使用副标题。

过滤图标位于关闭按钮旁，打开过滤弹窗；按能力提供规则名字、启用/关闭、消息类型、接收对象类型、精确 ID 和通知范围。过滤只影响列表，不改变整组保存、清空或分享的语义。群条件统一显示为群组，QQ 提供用户和群组 OpenID。

通知管理支持规则发送时间及组合通知类别；全局范围保持四种预设，每类消息可配置无操作用户时回退管理员或跳过。规则时间与全局时间由后端取交集，窗口外跳过。

## 能力与授权

界面使用后端能力目录决定可用页面、规则条件和目标类型。缺少已验证群组或私聊能力的平台不显示对应可信筛选条件。网页界面不自行判定真实平台身份。

渠道授权支持单条及批量通过、拒绝、停用、删除；已授权删除需要二次确认，批量审批明确授予普通成员及操作范围。保存和通知回执的结果分别反馈。账号关联使用后端签发的短时一次性码，不在群聊消费。

Web Push 切号先取消旧端点，每个异步阶段校验当前账号和登记代次；设备 owner 由服务器确定。重试与迟到清理不能覆盖新账号登记，界面不发送用户名冒充所有者。

接口、数据库、授权和可靠投递合同由[后端设计](https://github.com/jxxghp/MoviePilot/blob/v3/docs/channel-refactor/design.md)维护；本仓库只维护界面和客户端生命周期。

## 通用核心与平台表单分离

公共设置页消费 `GET notification/channels` 的 `providers` 和按连接 ID 的 `capabilities`，不维护内置类型清单，不按平台名推导规则类型、线程、账号筛选、凭据或登录管理。平台值仍保留在分享格式内，用于阻止跨类型导入。

连接表单继续复用既有平台配置页。专属交互配置通过 `ChannelInteractionExtension` 使用 Vite 已有组件发现机制加载 `forms/<extension>.vue`；Discord 命令服务器表单读写 `platform_options`。未知扩展不渲染平台字段，保存时保留原选项，由后端模块执行实际校验。增加平台表单无需改共享设置页、规则弹窗或核心授权代码。

规则弹窗按能力显示线程及标签；不解释平台 ID 正则。新增合成渠道测试使用非数字线程，证明新平台能力只需后端描述；公开 API 的兼容由后端维持。能力描述不代表当前用户获准操作，最终审批、业务范围、连接/群组/线程隔离与凭据校验由后端执行。

## 独立平台补齐

provider 是后端模块协议 owner，传输标识及连接身份不能被前端当作权限。共享设置页保留全部目录项，并根据后端增量出现的新 provider 创建独立草稿；组件回归同时检查原有卡片仍存在，禁止通过缩减目录或复用 Web/WebAgent 证明扩展成功。前端生产源码保持 af33d57d 的能力驱动实现，本轮补齐验收和文档；前轮浏览器/构建证据只对相同生产源码复用。实际检查以本轮源码 path/HEAD/index_tree 和最新验收索引为准，手测运行环境未自动切换。
