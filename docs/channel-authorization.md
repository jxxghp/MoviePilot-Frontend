# 渠道授权界面

## 系统设置

「消息 & 交互」只展示一组「消息渠道」卡片，不提供第二层标签。卡片默认打开「连接配置」，通过标题栏切换图标或卡片「更多」菜单进入「通知管理」「交互管理」。菜单仅列出当前渠道支持的用途，三项分别保存，切换时保留各自未提交的输入。

卡片沿用下载器的关闭移除与拖拽样式，增加「更多」菜单。拖拽只更新草稿，点击卡片组「保存」后提交顺序。新建连接也需要页面保存。关闭图标会先显示对通知、交互、成员和任务的影响，再确认移除。

卡片组右侧提供「全局通知设置」和「渠道授权」。全局设置包含模板、发送范围和发送时间。单连接的目标与规则放在「通知管理」，首次使用方式、搜索后自动下载和 Discord 命令注册范围放在「交互管理」。关闭连接总开关会暂停该渠道全部收发。

首次使用可选四种模式。「人工审批」由管理员审批成员。「人工审批 + 规则审批」允许命中规则的新用户直接使用，其余用户可以申请。「规则审批」按规则准入。「无需审批」允许可向机器人发送消息的用户直接搜索、添加订阅和下载，选择时界面会提示公开群的操作风险。既有审批、停用和拒绝继续生效。

首次使用规则可选择搜索、订阅、下载及定时任务。创建后，如果交互策略或成员授权发生变更，旧规则任务需要重新创建。点击标题栏切换图标可以在三个管理页面间切换。

「搜索后自动下载」可选「关闭」「规则」「全部」。选择「规则」后，在「规则编辑」里配置该连接支持的匹配条件。每条规则有单独的开关和编辑弹窗，列表确认后再保存渠道卡片。QQ 的规则条件为「群组」和「用户」。已获下载权限的用户才会自动择优。原全局设置已删除，旧继承值转为关闭，连接上原先明确选择的关闭和全部保留。

## 通知投递规则

在内置渠道卡片打开「投递规则」。每张规则卡片选择消息类型、通知范围和接收对象，可独立编辑、启停和删除。列表支持搜索、导入、清空和分享。先保存规则列表，再保存对应的通知或交互管理页面。收到待确认规则时，指定明确的接收对象后再启用。

同一连接可将不同事件发送到不同的用户、群组或频道。Telegram 可指定话题。Web Push 和 AppPush 可从有效账号中选择，原账号绑定决定实际接收设备。全局通知范围约束规则，个人消息使用对应账号的地址。Discord 的命令注册服务器在「交互管理」设置。

## 成员审批与个人关联

系统管理员在用户管理右下角打开“渠道授权”。移动端通过同页底部操作菜单进入相同弹窗；用户列表仍只展示网页登录账号。

弹窗内处理待审批申请，或按交互连接和完整用户 ID 直接授权。审批时选择普通成员能力，定时任务默认关闭。授予渠道管理员须单独确认。拒绝、停用、恢复及能力编辑均在此完成。审批权限属于网页系统管理员。

各通知渠道配置已移除用户与管理员白名单，接收人、群组、话题和默认投递目标归入投递规则。旧草稿提交时清除已经迁移的授权键，后台迁移与身份约束见后端 `docs/channel-authorization.md`。

网页登录用户在个人信息 → 账号绑定中打开“关联渠道账号”，将一次性指令在五分钟内私发给机器人。关联码不放入 URL、日志或持久化存储，关闭窗口即清除显示。关联不代替管理员审批。

`src/api/authorization.ts` 对齐后端统一 Response envelope；管理窗口只消费脱敏实例和成员记录。加载失败支持重试，保存失败保留输入，关闭或卸载后忽略迟到响应。审批成功只更新服务器返回的授权快照，原业务请求不会自动重放。

组件测试通过真实 API 客户端和 MSW 验证审批、额外管理员确认、停用/恢复、错误重试、能力选择、关联码到期及关闭清理；布局及移动端操作另用真实浏览器验证。

新建连接的自动名称避开当前连接名。已删除连接的名字可重新使用，新连接分配新的稳定 ID，旧授权与投递记录不会迁移。

## 规则名字、过滤与发送时间

投递、首次使用和自动下载规则可设置名字。规则列表关闭图标旁的过滤按钮可按启用状态（全部、已启用、已关闭）、名字、接收对象类型和适用的精确 ID 筛选；通知规则还可按消息类型和通知范围筛选。过滤不改变保存或分享的整组规则。单条规则使用独立开关、编辑和删除图标，取消编辑保留原值。

投递规则可设置「通知发送时间」，按系统时区执行，包含起止分钟，支持跨午夜；相同起止时间表示全天。窗口外直接跳过，不补发。重试和分段发送在实际提交前复核窗口。相同目标多条规则命中时，任一窗口有效即可发送；个人通知仍不能通过规则转发给其他用户。

移除连接会直接删除连接、通知、交互及排序配置；历史成员与任务保留原稳定 ID，仅供查询，不继续执行。同名可重建并分配全新身份，不继承旧授权。旧版本的归档配置由迁移 `62c91ad8b057` 清理，不再占用名称，升级前需备份。历史名称预留方案已撤回。

## 通知范围的两层语义

全局发送范围已经覆盖四种预设：仅操作用户 `user`、仅管理员 `admin`、管理员和操作用户 `user,admin`、所有用户 `all`。其中管理员表示系统主管理员的通知身份，并非全部渠道管理员；所有用户仍受启用账号、绑定地址与渠道投递能力约束，不等于自动向每个平台的全体成员广播。

投递规则的 `audience` 筛选全局路由产生的管理员、个人或全体通知类别，`any` 不额外限制。它不能补发全局未选择的收件人。全局已有四种组合，不需要改成可勾选重复或互相包含选项的多选框。群组、明确 ID 与指定网页账号由接收对象字段处理；同时筛选管理员和个人事件可在同一规则多选对应类别，规则不扩大个人消息的收件范围。

已知兼容边界：普通消息选择“仅操作用户”时，若消息没有用户名或该用户不存在，旧路由仍可能回退管理员；有效用户未绑定地址时跳过，已确认订阅归属没有可用目标时也跳过。现在提供独立的“无操作用户时：跳过个人通知／回退管理员”策略，旧配置默认继续回退。

## 授权删除与批量管理

待审批、已授权、拒绝和停用记录均可删除。已授权记录需二次确认，确认框显示成员名称、平台 ID 和渠道；后台要求当前版本及 `confirm_approved`。删除撤销原稳定授权与派生规则任务授权，保留业务账号、订阅、下载和任务历史。重新申请生成新成员和内部身份，不恢复旧授权、账号关联或任务。删除不会永久阻止再次申请；持续禁止使用应停用记录，首次使用规则与开放策略仍按当前配置生效。

列表支持单选和全选当前搜索及状态结果，搜索、切换状态或重新读取会清空选择。批量通过与拒绝仅用于待审批，批量停用仅用于已授权，批量删除用于全部状态。每次最多一百条。批量操作先确认，批量通过统一授予普通成员角色，并明确选择本次允许的搜索、订阅、下载和定时任务操作，不批量提升管理员。

后台按稳定 ID 和 `updated_at` 比较更新；整批校验和提交在同一事务，任一状态、版本或身份冲突返回 409，所有状态变更与审批回执一起回滚。删除不排队发送已无法核验成员的回执，旧待发送回执与任务在执行时重新核验后失效。成员管理接口仅允许网页登录系统管理员，渠道管理员和内部令牌不能调用。

## W18 多选通知类别与无操作用户策略

投递规则支持 `audiences: ["admin", "user", "all"]` 的任意子集，分别表示管理员通知、操作用户通知和全体用户通知类别；空数组不额外限制宿主已解析的全局范围。`all` 是全体路由类别，不是全选按钮。旧 `audience` 单选字段仍能读取；新数组存在时优先使用，单一值投影回旧字段，多值或空集合在旧字段投影为 any。运行时与冻结的 Outbox 规则快照按有效数组匹配，不产生新的收件人。

多选个人类别仍只能使用绑定地址或允许受众中的指定账号，不能同时指定第三方用户、群组或 Webhook 接收个人通知。平台全体成员目标仅允许 `["all"]`，不能通过清空或混选管理员类别把个人或管理员通知广播到平台全体。界面按接收对象能力提供选项并校验，后台独立验证。

规则编辑复制数组，取消不污染外层草稿；过滤弹窗按多选类别任一值匹配，沿用全局的规则可单独用 any 筛选。分享升级为第二版，保留多选类别；导入接受第一版旧单选与第二版，拒绝未知类别、跨个人目标或平台全体扩大范围。旧客户端不应编辑无法理解的多选规则。

全局通知范围继续使用四种单选预设。每种消息类型新增 `missing_user: "admin" | "skip"`，默认 admin，兼容旧版找不到用户时回退管理员。skip 在无用户名或用户不存在时跳过个人通知分支；明确选中的管理员通知仍发送。已确认订阅归属失效，或有效用户没有绑定渠道地址，继续跳过，不因策略为 admin 而改发第三方。

全局页面在每类消息范围旁显示“无操作用户时”，不包含 user 的预设下禁用该控件并保留其选择，恢复个人通知时继续生效。普通回复、明确收件人和授权回执沿用各自路径，不受此策略影响。已有未确认的 Outbox 目标仍受原清单限制，不会因修改策略增加新目标；旧目标不再参与派发时遵循现有有限重试和诊断结算，不伪造成功。

本次为 JSON 配置与接口字段扩展，不改数据库表。默认值在读取时兼容旧记录，不批量重写手测配置；恢复旧后端时应恢复升级前备份，因为旧版严格规则模型不认识 audiences。此前关于规则层继续单选或仅通过两条规则组合的建议由本节替代，全局四项预设保持不变。

## 平台能力与配置表单

共享管理页面按后端能力显示选项，新增平台无需修改公共设置页。平台专属选项在对应连接表单或交互扩展组件中配置，后端始终复核；能力不会自动批准成员或扩大通知范围。线程和 ID 格式由后端平台模块校验。详见[设计](channel-settings/design.md)。
